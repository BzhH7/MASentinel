# system1_iterative_coding 运行结果复核

## 结论

- 被测系统整体已经跑起来：16 个 case 中 15 个进程正常返回 `0`，均注入并使用 `ds-v4-flash`。
- 原始结果里的 `MISSING_MESSAGE_EDGE` 主要是 trace 采集不足，不是被测系统没有运行。stdout 中已经能看到 `manager -> planner/programmer/reviewer` 的 AutoGen 对话边。
- `system1_iterative_coding_R2_003` 的超时由 MASentinel 生成的 `very_long_input` 触发，输入长度约 5110 字符，目标系统在启动阶段处理超长 prompt 时超时；这应归为测试框架/用例预算问题，不应计入被测系统 fault。
- 剩余较值得关注的是 `META_001` 的 `MISSING_TOOL_CALL`：现有 trace 未证明 `write_latest_iteration` / `write_settled_plan` 被真实调用。已在 runtime patch 中补充 system1 工具方法的 `MAS_TRACE` 记录，重跑后可以确认这是工具兼容问题还是旧 trace 不足。
- 本项目故障归因边界只包含应用层代码和 AutoGen 框架/配置/工具集成层。模型服务鉴权/限流/超时、模型回答风格或知识不足不计入目标系统故障，会进入 `non_target_issues.json` 或误报审计。

## 已修复的评测系统问题

- 从 AutoGen stdout 中解析 `agent (to agent):` 消息边，避免因未导入深度 instrumentation 而误报消息路由缺失。
- 对 system1 的关键工具方法发出 `MAS_TRACE`，包括 `write_latest_iteration`、`write_settled_plan`、`write_latest_iteration_comments`、`retrieve_latest_iteration`、`retrieve_latest_iteration_comment`。
- 将 `very_long_input` 从 300 次重复降到 40 次重复，并增加 `testing.max_case_input_chars` 输入预算，默认截断超长生成用例。
- 对“超长生成输入导致尚未进入有效 agent workflow 就超时”的情况标记为 `TESTCASE_SETUP_TIMEOUT`，不进入目标系统 fault 分类。

## 复核后的剩余问题

- `META_001`: 仍有 2 个工具调用缺失和 1 个 metamorphic relation 失败，需要重跑后利用新的工具 trace 再确认。
- `R2_003`: 归类为 `TESTCASE_SETUP_TIMEOUT`，属于测试用例生成/预算问题，不计入目标系统缺陷。
